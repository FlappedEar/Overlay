# Media and color policy

Source raster, bit depth, and color characteristics are data, not presets. FlappedEar does not impose a product-level 4K ceiling. A native export is accepted only when the active QRhi renderer, selected HEVC encoder/profile, and resource preflight support the exact request.

`MediaProbe` retains coded and display raster, exact and average rates, codec/profile, pixel format, optional bit depth and video bitrate, sample aspect ratio, optional rotation, and the raw FFmpeg color range, matrix, transfer, and primaries. Missing probe fields remain unset. Bit depth uses `bits_per_raw_sample` when valid and a conservative allowlist of known pixel formats otherwise; unknown formats do not become 8-bit by default.

The raw color fields are authoritative. A small policy classification distinguishes SDR, HLG HDR, PQ HDR, Log/extended, possible HDR, and unknown sources. 10-bit is not synonymous with HDR, and BT.2020 alone is not treated as a complete HDR policy: BT.2020 primaries with a known SDR transfer (`bt2020-10`, `bt2020-12`) are SDR. A stream is classed as possible HDR (unverified) when it carries mastering-display or content-light side data whatever its transfer tag, or has BT.2020 primaries with a missing or unrecognised transfer, because either can be HLG or PQ with the transfer tag lost.

The validated default export policy preserves 8-bit SDR as HEVC Main and 10-bit SDR as HEVC Main10. Stage A remains lossless premultiplied FFV1/BGRA. For 10-bit Stage B, the authored overlay is explicitly unpremultiplied and straight-alpha blended in `yuv420p10` before conversion to the encoder's P010 surface. Validation covers decoded RGB fidelity as well as final pixel format, bit depth, codec profile, and known color tags. The QML overlay remains authored in its existing SDR/sRGB-like space.

HLG, PQ, Log/extended, and possible-HDR material requires a validated color-managed compositor. It is detected and rejected during export preflight today. Unsupported HDR/Log material must never be silently converted to 8-bit SDR, silently tone-mapped, or described as supported merely because metadata can be copied.

Rotation and sample aspect ratio are retained and shown through the media model. Import, probe, playback, and editing do not alter their behavior, but the centralized `ExportMediaProfile` fails export preflight for non-zero rotation or a valid non-square SAR; there is no implicit rotation, scale, crop, or metadata-only transform. Complete display-transform preservation remains pending. Native-resolution architecture is deterministic-tested through 8K representation; production 8K support remains a runtime renderer/encoder decision and still needs real hardware/media validation.

Recommended bitrate is a continuous pixel-rate curve anchored at 12.5 Mbps for 1080p30: `12.5 Mbps × (pixelRate / 1080p30)^0.66`, with a 1.15 multiplier for depths above 8-bit and quality multipliers of 0.70/1.00/1.30. Custom bitrate is defensively bounded to 0.5–500 Mbps. This supports future rasters without an arbitrary 4K plateau while retaining the established 1080p and 4K ballpark.

One private macOS validation fixture (GoPro HERO11, August 2026) was HEVC Main 10 at 5312×2988, `60000/1001`, full-range BT.709. Native 5312×2988 and 3840×2160 exports both passed with HEVC Main 10, `yuv420p10le`, and the same range/matrix/transfer/primaries. A separate 3840×2160, `60000/1001`, full-range BT.709 fixture exposed and then validated the transparent-chroma fix through a 351-frame production VideoToolbox export with the real overlay; an overlay-free decoded crop measured 44.86 dB RGB PSNR against the source. This confirms the SDR Main10 path on that renderer/VideoToolbox configuration only; it does not validate HDR/Log or production 8K support.

## Runtime filter capability

Before rendering telemetry, export executes a tiny production composition graph for the selected bit depth. An installed encoder alone does not establish alpha-filter compatibility. Unsupported filters fail early; the required straight-alpha Main10 path is not replaced by a color-changing fallback. Candidate acceptance must also inspect real decoded output, as described in [beta-acceptance.md](beta-acceptance.md).
