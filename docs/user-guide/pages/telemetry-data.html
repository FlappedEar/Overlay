Telemetry data reference

What the application reads from VBO and RCZ files, how channels are recognised, and how missing data is treated.

Principles

  • Missing is not zero. When a channel has no value at a moment, widgets show a dash and charts leave a gap. Gaps in a recording are never bridged in analysis.
  • Nothing is invented. A missing brake channel is never estimated from G or speed in the overlay, and one channel is never silently replaced by another. Where analysis does infer something (for example braking from deceleration), it says inferred.
  • Recorded values are not changed. The overlay smooths what it displays slightly; analysis uses raw samples.
  • Heart rate comes from the imported VBO or RCZ recording. There is no separate heart-rate import.

VBO files

A VBO file is a text file with a [column names] section and a [data] section. The application has been verified with VBO exports from RaceChrono Pro 10.2.4. Other VBO files are read in the same general way, with these differences:

  • GPS position is used only when the coordinate unit is known. RaceChrono Pro 10.2.4 files are recognised automatically. For other files, add a line coordinate units = degrees (or arc-minutes) to the [header] section. Without it, GPS position, the track map, lap timing and pairing are unavailable; all other channels still import, with the warning GPS coordinates and timing gates unavailable.
  • Timing gates (start/finish line) from other RaceChrono versions are ignored with the warning Timing gates ignored: this RaceChrono exporter version has not been validated. Telemetry remains available, but laps cannot be derived.
  • The recording's date and time are read only from a recognised RaceChrono export. Without them, the recording has no clock and is ordered by import order.

Rows with invalid, duplicate or backwards timestamps are skipped with a warning. Timestamps crossing midnight are handled. Columns without any number are dropped.

RaceChrono G channels

For lateral and longitudinal G, export VBO from RaceChrono with the calculated acceleration channels (latacc-calc, longacc-calc) enabled. These are preferred automatically. RCZ archives contain only the phone's raw accelerometer axes, which are not aligned with the car, and no calculated G.

RCZ files

An RCZ file is a RaceChrono session archive. Supported: a single, uninterrupted session shared from RaceChrono Pro (developed against version 10.2.4). Each channel keeps its own sample rate; nothing is resampled. A pause longer than three times a channel's normal sample spacing is a gap.

Refused with a message: resumed sessions, archives with several sessions, encrypted, split or ZIP64 archives, sessions longer than 24 hours, and archives whose GPS is missing. Unknown channel types are left out with a warning. Video and synchronization data stored inside the archive are not imported.

How channels are recognised

Widgets and analysis use a channel's purpose (speed, RPM and so on). The application finds the channel by name, ignoring upper and lower case. For VBO files:

RPMrpm, rpm-…, names containing engine speed
Throttlenames containing throttle or accelerator pedal; an accelerator-position channel with data takes priority
Brakebrake, brake-…, names containing brake pressure or brake pedal
Heart ratenames containing heart rate, or exactly hr or bpm

Longitudinal Glongacc-calc first, then longacc, longitudinal accel…, longitudinal g, gy
Gearnot recognised automatically; select it in the widget

Any channel can still be chosen by name in a widget's Source channel.

Tyre channels

The Tyres widget finds channels whose name contains tyre or tire, either temp/temperature or pressure/press, and one corner: fl, fr, rl or rr (also lf, rf, lr). Example: tyre_temp_fl.

  • Temperature is shown in °C. A channel declared in °F is converted; units are only read from RCZ files, so a VBO channel is always treated as °C.
  • Pressure in bar, psi or kPa is converted to the chosen display unit. If the unit is not declared (always the case for VBO files), it is judged from typical values.
  • An exact 0 is treated as "no reading yet", because tyre-pressure sensors report 0 before their first reading.

Display smoothing

To keep the overlay readable, displayed values are averaged over a short time window (about 0.1 to 0.25 seconds, depending on the channel; gear is not smoothed) and the last value is held for up to 0.75 seconds (2 seconds for heart rate) across a missing sample. Analysis charts and results always use the raw samples.
